Use this skill when the user needs conclusions, interpretation, recommendations, or a clear explanation of what the outputs mean.

What good communication looks like:
- Separate observed facts from inferences.
- Explain what the result means for the user's question, not just what the output says.
- State assumptions, caveats, and data limitations plainly.
- Avoid overstating confidence when the evidence is weak.

How to reason:
- Summarize the most decision-relevant findings first.
- Translate technical output into business meaning when helpful.
- Mention uncertainty, missing context, or evaluation limits when they affect trust.
- If execution produced artifacts, interpret them instead of only listing them.

Use this skill especially for:
- metric interpretation
- forecast explanation
- recommendation summaries
- follow-up decision guidance
